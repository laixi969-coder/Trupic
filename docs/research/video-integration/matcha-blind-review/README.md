# 抹茶拿铁商家盲评

第一次体验可以先打开 [自己盲选](自己盲选.html)。用普通浏览器打开即可播放两条完整的 15 秒成片。每份作品各选「可以直接发」或「需要修改」，退稿须写原因，再选偏好并提交。文件使用营销助理的评审组件，A/B 顺序在首次打开时随机分配，反馈仅保存在当前浏览器。重新打开可看结果，也可重新随机盲选。

[36 秒营销助理网页实录](walkthrough.mp4) 连续播放了两个匿名样片，展示逐版评价、提交和揭晓。两段声音来自实际播放的成片混音，按屏幕播放时间同步。此记录由测试操作员在本地单商家验收账号完成。

## 揭晓后的记录

演示采用「本周五到店价已定为 19.90 元」作为发布条件。操作员从匿名成片中听到一版报 18.90、一版报 19.90，退回前者并选中后者。原稿对应的 18.90 在原活动中是正确价格。这次同时改变了价格和片尾读法，不能据此单独判断哪种语气更受商家欢迎。

| 实际记录项 | 首次交付 | 修改交付 |
| --- | --- | --- |
| 这次演示能否直接发布 | 需要修改 | 可以直接发 |
| 退稿原因 | 本次周五到店价是 19.90 元，片尾仍报 18.90 元，需要改价 | — |
| 从本次需求提出到交付 | 31 秒 | 28 秒 |
| 从确认制作到交付 | 30 秒 | 13 秒 |
| 该次制作实际消耗 | 12 积分 | 1 积分 |

人工参与改稿用时留空。原作品的提交事件和扣费流水可以验证上述系统用时和积分。盲评开始和结束时的账户余额均为 107 积分。测试意见计入演示记录，商家统计仍为 0 份回应。[原活动成片与改稿凭据](../matcha-friday-revision/README.md) · [盲评接口、独立听写和计时记录](checks.json)

本次浏览器在揭晓前只请求了评审及 A/B 媒体地址。刷新使用同一顺序；媒体支持分段请求。另一个工作空间请求任一匿名样片均被拒绝。独立的离线试玩可在无网络环境播放、提交、刷新查看及重新开始；其答案不会回写正式评审。

## 本机复验

从项目根目录运行 `npm run build`，然后运行 `.venv/bin/python scripts/proof-merchant-blind.py --seed <抹茶改价验收目录>`。脚本先核对原商家作品及两个 MP4 摘要，把单商家验收数据库备份到临时目录，再通过营销助理 API 和 Chrome 页面提交演示答卷。留空 `--seed` 时，会从系统临时目录中寻找与现有交付记录严格匹配的验收账户。本机需要 Chrome、FFmpeg、此前配置的 Whisper 和项目依赖。[复验脚本](../../../../scripts/proof-merchant-blind.py)
